# редакторы

### математический

Математический редактор ограничен по добовлению блоков, из-за чего формулы не могут принимать более сложный вид, математические операции лучше вынести из блоков чтобы использовать их как инстансы для новых блоков или разделении имеющихся на 2, при добовлении элементов не должна стиратся вся формула, так же как и при нажатии на *"удалить блок"* должен стираться 1 блок формулы а не вся формула.

### Графики

**+Визуальный фикс**: графики лучше рендерить во всю ширину блока так они смогут вместить большее количество значений сохранив визуальный вид.

Блоки для ввода значений не выбираются на Windows корректно, пропала подсветка блоков, из-за чего редактором не удобно пользоватся без изменения заранее заготовленного шаблона.

нет ограничений по количеству вводимых значений при этом интефейс колонок накладывается на интерфейс окна, в случаях когда колонки не помещаются в заранее выделенное окно

## Пользовательский опыт

### Обработка алиасов

необходимо дополнить параметры запуска программы чтобы при полученнии строки ведущей к файлу, проверять наличие этого файла и открывает его внутри программы вместо стандартной заглушки, сохранение производится так же в открытй файл

### Внедрение в контекстное меню Windows

Для удобства использования сделать ссылку на программу для контекстного меню "Открыть как" где вместе с запуском программы вней будет открыть файл полученный через алиасы

### Linux

На Linux при установке, необходимо прописывать "ярлычки" программы в стандартные пути которые используют популярные окружения для обновления списков программ (меню типа "Пуск" для запуска программ или иные лаунчеры программ), так же необходима возможность запуска через консоль



### Создание строки и перенос коретки на нее при 2 клике на конец файла

Возникают ситуации когда из-за Блока кода или блоков формул/графиков не возможно перенести каретку т.к. график находится на последней строки, при этом коретка блокируется в определенно позиции из которой ее сложно вытащить, так же эта функция является просто удобной

# Issues

## refactor: единый безопасный способ открытия документа по пути #1

Зачем



Открытие через меню уже работает, но его логика находится внутри App::open() и связана с файловым диалогом. Для аргументов запуска и Drag \& Drop нужна общая операция, иначе проверка несохранённых правок, импорт и сброс состояния начнут расходиться.

Текущее устройство



В src/main.cpp есть App::open(), confirm\_discard(), save() и save\_as(). Загрузка определяет CommonMark/GFM и обновляет документ, историю и заголовок. В src/markdown\_io.cpp чтение и запись используют строковый путь в стандартных потоках; корректность кириллицы на Windows ещё не проверена.

Предлагаемый подход



    Выделить операцию открытия по пути с результатом «открыт / отменён / ошибка»; меню оставить адаптером выбора файла.

    Проверять путь и загружать во временные данные. Заменять текущий документ только после успешного чтения/импорта и разрешения несохранённых изменений. Продумать порядок сохранения и чтения, включая повторное открытие того же файла: нельзя загрузить устаревшую копию после сохранения.

    При успехе согласованно обновлять диалект, file\_path, modified, курсор, выделение, прокрутку, историю и заголовок. Закрывать редакторы блоков и временные меню, связанные со старым документом.

    Успешное внешнее открытие убирает приветствие, не меняя сохранённую настройку его показа.

    Проверить единый контракт кодировки путей; на Windows обеспечить Unicode при чтении, записи и определении расширения, например через корректное преобразование UTF-8 в filesystem::path. Не считать проблему Unicode уже воспроизведённой.

    Ошибки показывать понятным сообщением RU/EN; файл при неудачном открытии не создавать.



Критерии приёмки



    Меню использует общую операцию; обычное открытие и автоопределение диалекта работают как раньше.

    Ошибка чтения/импорта и отмена не заменяют текущий документ и не переключают его диалект.

    Сохранить / не сохранять / отменить корректно обрабатываются; отмена Save As и ошибка записи прерывают замену документа.

    Успешное открытие сбрасывает состояние старого документа; Ctrl+S сохраняет в новый путь.

    Чтение и запись путей с кириллицей и пробелами работают на Windows; пустой файл считается допустимым документом.



Проверка



Сборка и существующий headless selftest. Добавить целевые проверки общей операции: успешная загрузка, пустой файл, ошибка чтения, отсутствие частичной замены состояния. Вручную проверить все ответы на запрос сохранения, отмену Save As, повторное открытие того же файла и Unicode-пути.

Границы



Без вкладок, single-instance IPC и новых форматов импорта. Операция служит основой следующих задач; сама по себе не регистрирует ассоциации.

Связи



Нет. Основа для #2 и #3.

Общий порядок и границы выпуска: #5.



## fix: открывать Markdown-файл, переданный аргументом запуска #2

Проблема



При запуске приложения с путём к Markdown открывается стартовый экран/демодокумент, а переданный файл игнорируется. Из-за этого ручное назначение приложения обработчиком .md в Windows не даёт ожидаемого результата.

Как воспроизвести



    Создать существующий файл D:\\Documents\\PROBLEMS.md с узнаваемым текстом.

    Запустить marked-text-down.exe "D:\\Documents\\PROBLEMS.md" (в PowerShell при необходимости использовать оператор \&).

    Сравнить содержимое окна с файлом.



Фактически: переданный документ не открывается.

Ожидается: документ открыт и доступен для редактирования; заголовок и Ctrl+S относятся к нему.

Причина по коду



В main() разбирается только --selftest; остальные аргументы не используются для открытия документа. Инициализация создаёт демодокумент и применяет настройку приветствия.

Предлагаемый подход



После успешной инициализации передать позиционный путь в общую операцию загрузки. Использовать аргументы, предоставленные SDL/main: не собирать командную строку обратно и не удалять кавычки вручную. Проверить кодировку аргументов на Windows для установленной версии SDL3.

Контракт первой версии



    Один позиционный путь; абсолютные пути и относительные к рабочему каталогу запуска.

    Успешное открытие убирает приветствие только в текущем запуске.

    Запуск без аргументов сохраняет поведение; --selftest \[screenshot\] сохраняет текущий контракт.

    Неизвестные параметры, несколько путей, папка, отсутствующий или недоступный файл дают понятную ошибку. Ошибка не создаёт файл; при неуспешном запуске с документом предусмотреть ненулевой код завершения.

    Каждый запуск создаёт отдельный процесс/окно; доставка в существующее окно не требуется.



Критерии приёмки



    Пример из воспроизведения открывает указанный документ без стартовой заглушки поверх него.

    Пути с пробелами, кириллицей и относительные пути работают; пустой файл открывается.

    Ctrl+S записывает изменения в переданный файл.

    Ошибочные аргументы не игнорируются молча и не создают отсутствующие документы.

    Обычный запуск и selftest не сломаны.



Проверка



Целевые тесты разбора аргументов и открытия через общий метод; сборка и selftest. Вручную проверить реальный exe из каталога с пробелами и кириллицей, запуск из другого рабочего каталога и ручное «Открыть с помощью» Windows.

Границы



Регистрация в установщике — отдельная задача. Shell alias и ассоциация расширения — разные механизмы; этот fix обеспечивает необходимую для обоих передачу пути.

Связи



Зависит от #1 (общая безопасная загрузка).

Общий порядок и границы выпуска: #5.

## feat: открывать Markdown перетаскиванием файла в окно #3



Пользовательский сценарий



Можно перетащить Markdown из Проводника или файлового менеджера в окно редактора и сразу начать редактирование, без Ctrl+O.

Текущее состояние



В обработчике событий src/main.cpp нет поддержки drop. Открытие из меню уже существует; новая функция должна использовать общую операцию загрузки, включая защиту несохранённых изменений.

Поведение первой версии



    Один .md, .markdown или .txt без учёта регистра открывается как документ, включая drop поверх приветствия.

    При несохранённых правках действует сохранить / не сохранять / отменить. Отмена и ошибка оставляют текущий документ.

    Несколько файлов за один жест, папки и неподдерживаемые типы отклоняются одним понятным сообщением RU/EN без частичного открытия.

    Drop означает замену открытого документа, а не вставку текста или вложения.



Предлагаемый подход



Использовать SDL3 drop-события в App::dispatch(). Перед реализацией сверить события начала, файла и завершения, доступность drop и правила владения данными с документацией используемой версии SDL3. Копировать пути в собственное состояние до окончания срока жизни данных события; не переносить правила освобождения памяти из SDL2.



Собирать файлы до завершения одного жеста и только затем валидировать и открывать: иначе два файла могут последовательно заменить документ или вызвать несколько запросов сохранения. Сбрасывать накопленные данные после обработки/отклонения жеста. Проверить поведение при открытом модальном редакторе блока: его правки нельзя терять в обход обычной логики защиты документа.

Критерии приёмки



    Один поддерживаемый файл открывается через общий метод; имя, диалект, история и Ctrl+S соответствуют ему.

    Кириллица и пробелы в пути поддерживаются; приветствие не перекрывает успешно открытый документ.

    Отмена и ошибки не заменяют документ; несколько файлов отклоняются целиком.

    Последующий корректный drop работает после неуспешного жеста.



Проверка



Добавить в selftest синтетические последовательности drop для одного файла, нескольких файлов и повторного жеста после отказа. Проверить ошибки путей и расширения в разном регистре. Реальное перетаскивание вручную проверить на Windows и Linux: синтетические события не проверяют интеграцию с оболочкой.

Границы



Без вставки изображений, перетаскивания выделенного текста, переупорядочивания блоков и нескольких документов за жест. Визуальная подсветка зоны drop может быть последующим улучшением.

Связи



Зависит от #1 (общая безопасная загрузка).

Общий порядок и границы выпуска: #5.



## feat(windows): зарегистрировать Markdown в «Открыть с помощью» #4



Проблема



Установщик создаёт ярлыки, но не регистрирует редактор обработчиком Markdown. Пользователю приходится искать exe вручную; после поддержки аргумента запуска приложение должно быть доступно в стандартном выборе редактора Windows.

Основа



installer.nsi — Unicode NSIS installer с установкой в Program Files, правами admin и записями HKLM. Регистрация ассоциаций пока отсутствует.

Ожидаемое поведение



После установки Marked-text-down предлагается в «Открыть с помощью» для .md и .markdown. Пользователь может самостоятельно выбрать его по умолчанию. Уже выбранный обработчик не меняется без действия пользователя.

Предлагаемый подход



Перед реализацией сверить официальную схему Microsoft для ProgID, OpenWith, Applications/SupportedTypes и при необходимости Default Programs/Capabilities; выбрать минимальный набор записей, который выполняет критерии на поддерживаемых Windows.



    Использовать собственный ProgID и команду открытия вида "$INSTDIR\\marked-text-down.exe" "%1" с корректным NSIS-экранированием.

    Согласовать scope регистрации со scope установки, проверить 64-битное представление реестра.

    Зарегистрировать имя/описание приложения и доступную иконку; уведомить оболочку об изменении ассоциаций, если необходимо.

    Не перезаписывать UserChoice и не назначать приложение по умолчанию принудительно.

    При обновлении актуализировать путь. При удалении убирать только собственные ключи/значения; не удалять целиком общие ключи расширений и чужие обработчики. Проверить владение удаляемыми записями.

    В README описать выбор через «Открыть с помощью», пример запуска с путём, Drag \& Drop и особенности portable. Portable не пишет реестр автоматически.



Критерии приёмки



    После установки приложение доступно для .md/.markdown в «Открыть с помощью» и открывает выбранный файл.

    После ручного выбора по умолчанию двойной клик открывает нужный документ.

    Прежний выбор по умолчанию сохраняется до действия пользователя; .txt не перехватывается.

    Команда работает при пробелах/кириллице в путях exe и документа.

    Обновление не создаёт дубликатов, удаление убирает собственную регистрацию и сохраняет чужую.

    README объясняет installed/portable сценарии.



Проверка



Собрать NSIS installer и проверить в тестовой Windows: чистую установку, обновление, выбор приложения, повторный запуск и удаление. Проверить ситуацию с уже назначенным другим Markdown-редактором и сохранность его регистрации после удаления. Зафиксировать версию Windows и результаты в PR.

Границы



Без URL-протокола, изменения системных алиасов и single-instance IPC. Пункты регистрации здесь — направление реализации; конкретные ключи нужно проверить по документации, а не копировать наугад.

Связи



Зависит от #2 (открытие файла аргументом запуска).

Общий порядок и границы выпуска: #5.



## Открытие Markdown извне и Drag \& Drop: план интеграции #5

Цель



Сделать редактор удобным для открытия существующих Markdown-файлов: из командной строки, через ассоциации Windows и перетаскиванием в окно.

Обратная связь



При ручном назначении приложения для .md открывается стартовая заглушка вместо документа. Проверка исходников подтвердила: main() обрабатывает --selftest, но не путь к документу. Drag \& Drop и регистрация обработчика в установщике отсутствуют.

Декомпозиция и порядок реализации



    refactor: единый безопасный способ открытия документа по пути #1 — общая безопасная загрузка по пути, корректность Unicode и защита несохранённых изменений.

    fix: открывать Markdown-файл, переданный аргументом запуска #2 — исправление игнорирования аргумента запуска; зависит от refactor: единый безопасный способ открытия документа по пути #1.

    feat: открывать Markdown перетаскиванием файла в окно #3 — открытие одного файла через Drag \& Drop; зависит от refactor: единый безопасный способ открытия документа по пути #1.

    feat(windows): зарегистрировать Markdown в «Открыть с помощью» #4 — регистрация «Открыть с помощью», удаление записей и инструкция; зависит от fix: открывать Markdown-файл, переданный аргументом запуска #2.



Рекомендуемый порядок: #1 → #2 → #3 → #4. После #2 уже можно проверить ручное назначение exe через Windows. Каждую задачу удобно оформлять отдельным PR со ссылкой на issue и результатами проверки; общую задачу закрывать после всех четырёх.

Решения первой версии



Один документ на окно; отдельный запуск создаёт отдельное окно. Drop открывает один .md/.markdown/.txt; несколько файлов отклоняются целиком. Успешное внешнее открытие убирает приветствие, сохраняя пользовательскую настройку. Windows не получает нового редактора по умолчанию без выбора пользователя. Portable поддерживает аргументы и ручное «Открыть с помощью» без автоматической регистрации.

Вне объёма



Вкладки, доставка в существующий процесс, URL-протокол, вставка изображений и перетаскивание текста. Термин «алиас» из обратной связи здесь трактуется как назначение обработчика расширения; отдельный shell alias не требуется.

Готовность выпуска



    Пример marked-text-down.exe "D:\\Documents\\PROBLEMS.md" открывает указанный документ.

    Drop и «Открыть с помощью» приводят к тому же результату, что открытие из меню.

    Ошибки и отмена не приводят к потере документа; сохранение пишет в правильный файл.

    Пробелы и кириллица работают в путях exe и документа.

    Существующий selftest и сборки проходят; интеграция оболочки проверена вручную на Windows, drop — на Windows/Linux.
